# Gmail Checklist Delivery and Resend Contact Storage Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Send the existing 25-item checklist through Gmail without a custom domain while saving only follow-up-consenting visitors to the existing Resend Segment.

**Architecture:** A focused Gmail adapter owns Nodemailer transport creation and message delivery. The existing Vercel handler continues to validate requests and optionally creates a Resend Contact, then delegates delivery to the Gmail adapter. Gmail and Resend secrets remain server-only Vercel environment variables.

**Tech Stack:** Node.js 20+, Vercel Functions, Nodemailer, Gmail SMTP, Resend Contacts REST API, Node test runner

## Global Constraints

- Initial sending volume is approximately 30 recipients; personal Gmail is for this small validation only.
- The existing HTML and plain-text 25-item checklist content must remain unchanged.
- Only users who explicitly select follow-up consent may be stored in Resend Contacts.
- No Supabase or other application database is introduced.
- Secrets must never be written to source files, Git history, command output, or application logs.
- A Resend Contact failure must not prevent the one-time Gmail delivery.

```js
import nodemailer from 'nodemailer';

export function createGmailSender({
  env = process.env,
  createTransportImpl = nodemailer.createTransport,
} = {}) {
  if (!env.GMAIL_USER || !env.GMAIL_APP_PASSWORD) {
    throw new Error('GMAIL_NOT_CONFIGURED');
  }

  const transport = createTransportImpl({
    service: 'gmail',
    auth: { user: env.GMAIL_USER, pass: env.GMAIL_APP_PASSWORD },
  });

  return ({ to, subject, html, text }) => transport.sendMail({
    from: `자취선배 <${env.GMAIL_USER}>`,
    replyTo: env.GMAIL_USER,
    to,
    subject,
    html,
    text,
  });
}
```
