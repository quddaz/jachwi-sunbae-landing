# 자취선배 고시원 체크리스트 랜딩 페이지 설계

## 1. 목표

인스타그램 릴스·쇼츠 광고를 통해 유입된 사용자가 모바일 인앱 브라우저에서 짧은 시간 안에 고시원 계약 전 점검의 필요성을 이해하고, 이메일을 입력해 무료 체크리스트를 받도록 만든다.

핵심 성과는 다음 두 가지다.

- 방문자가 이메일 발송을 요청하는 전환
- 후속 사용자 검증에 활용할 수 있는 이메일 연락처 확보

이번 범위는 광고용 단일 랜딩 페이지와 이메일 발송 기능까지다. 매물 기록, 비교, 계약서 스캔 등 본 서비스 기능은 포함하지 않는다.

## 2. 대상 사용자와 브랜드

- 대상: 처음 고시원을 알아보거나 계약 경험이 적은 청년·자취 초보자
- 유입 환경: 인스타그램 릴스·쇼츠 광고에서 열린 모바일 인앱 브라우저
- 서비스명: `자취선배`
- 말투: 직접 살아본 선배가 후배에게 현실적인 조언을 건네는 친근한 존댓말
- 표현 원칙: 경험담의 생생함은 유지하되 욕설, 비하, 검증되지 않은 절대적 단정은 사용하지 않는다.

## 3. 선택한 콘텐츠 접근법

다음 세 후보 중 `손해 경고형`을 기본 구조로 선택하고, `선배 편지형`의 말투와 `점검표형`의 구체적인 항목 수를 결합한다.

- 손해 경고형: 광고 유입 직후 문제를 빠르게 인식시키지만 과도하면 불안을 조장할 수 있다.
- 선배 편지형: 친밀감과 신뢰가 높지만 첫 화면의 주목도가 상대적으로 약하다.
- 점검표형: 제공 가치가 구체적이지만 아직 제품을 모르는 사용자에게는 도구 소개처럼 보일 수 있다.

최종 방향은 강한 문제 인식으로 시작하되, 모든 설명은 선배의 실제 경험과 조언처럼 풀어낸다.

## 4. 페이지 구조와 카피

### 4.1 상단 히어로

- 브랜드: 자취선배
- 보조 문구: `고시원 계약 전 5분만`
- 제목: `사진만 믿고 계약했다가 한 달 내내 후회할 수 있어요`
- 설명: 사진에는 보이지 않는 벌레, 소음, 냉방, 환기 문제를 계약 전에 확인해야 한다는 메시지
- 첫 번째 CTA: `무료 체크리스트 받기`

### 4.2 실제 경험에서 나온 핵심 조언

랜딩 페이지에는 전체 체크리스트를 모두 공개하지 않고 다음 항목을 짧은 카드나 단계형 블록으로 보여준다.

1. 로드뷰로 건물 저층의 음식점과 술집 확인
2. 위·아래층의 음악학원, 댄스학원, 술집 등 소음 가능 업종 확인
3. 중앙냉방보다 개인 에어컨 우선 고려
4. 내창보다 외창 우선 고려
5. 책상과 의자의 실제 사용 가능 여부 확인
6. 첫 계약은 가능하면 한 달 단위로 시작

음식점이 있으면 벌레가 반드시 발생한다는 식의 표현 대신, 업종과 층간 거리에 따라 벌레·냄새 가능성을 확인하라는 행동 지침으로 쓴다.

### 4.3 주거 혜택 훅

- 제목: `이사할 지역에서 받을 수 있는 주거 혜택, 알고 계세요?`
- 설명: 청년 월세, 이사비·중개보수, 보증료 등은 지역과 신청 시점에 따라 달라질 수 있으므로 본인 지역의 최신 공고를 확인해야 한다.
- 제공 가치: 체크리스트 이메일에 공식 사이트에서 지역별 혜택을 확인하는 방법과 링크를 포함한다.

특정 지원 금액이나 자격 조건은 랜딩 페이지에 고정하지 않는다. 구현 시점의 공식 정부·지자체 출처를 확인해 링크와 일반적인 지원 범주만 제공한다.

### 4.4 전환 구간

- 강조 문구: `지금 보신 내용은 일부예요`
- 가치 문구: `총 25개의 고시원 점검 항목과 놓치기 쉬운 주거 혜택 확인법을 받아보세요`
- 필드: 이메일 주소 1개
- 개인정보·마케팅 수신 동의: 체크리스트 발송에 필요한 이메일 처리 동의는 필수, 후속 인터뷰나 서비스 소식 수신은 선택으로 분리
- CTA: `자취선배의 체크리스트 무료로 받기`
- 성공 상태: `체크리스트를 보냈어요. 메일함을 확인해 주세요.`
- 실패 상태: 입력 오류와 발송 오류를 구분하고 다시 시도할 수 있도록 안내

## 5. 체크리스트 이메일

이메일 본문에 다음 25개 점검 항목을 체크 가능한 형태로 제공한다.

### 방문 전 조사

1. 로드뷰에서 건물 1층과 인접 층의 업종 확인
2. 음식점의 종류와 방까지의 층간 거리 확인
3. 위·아래층의 음악·댄스 관련 시설 확인
4. 술집 등 야간 소음 가능 업종 확인
5. 전화 응대에서 운영자의 설명 태도 확인

### 방과 생활 옵션

6. 개인 에어컨 또는 중앙냉방 여부 확인
7. 중앙냉방의 운영 시간 확인
8. 내창 또는 외창 여부 확인
9. 창문을 통한 실제 환기 가능 여부 확인
10. 습기와 곰팡이 흔적 확인
11. 책상의 높이와 작업 공간 확인
12. 의자의 상태와 장시간 사용 가능 여부 확인
13. 식사 제공 범위 확인
14. 개인 냉장고 유무와 작동 소음 확인

### 현장 점검

15. 수납공간 확인
16. 벽 재질과 방음 상태 확인
17. 화장실 수압 확인
18. 온수가 나오는 시간 확인
19. 복도와 공용공간의 청소 상태 확인
20. 방 내부의 청소 상태 확인
21. 세탁기 수와 이용 가능 시간 확인
22. 빨래 건조 공간 확인
23. 침대 커버 아래 곰팡이·해충 흔적 확인

### 계약 전 확인

24. 장기계약 할인 조건과 중도 퇴실 조건 확인
25. 처음에는 한 달 계약이 가능한지 확인

이메일 하단에는 복지로, 정부24 또는 보조금24, 해당 지자체 공식 공고 등 최신 주거 혜택을 직접 확인할 수 있는 공식 경로와 `지원 조건은 지역과 시점에 따라 달라질 수 있다`는 안내를 넣는다.

## 6. 시각 디자인

- 모바일 우선 단일 열 구조, 데스크톱에서는 콘텐츠 최대 너비를 제한해 집중도를 유지
- 따뜻한 아이보리 배경과 주황색 강조색
- 경고는 붉은색 남용 대신 굵은 문장과 대비가 높은 강조 블록으로 표현
- 카드 남발 없이 핵심 사례와 체크리스트 미리보기만 구분
- 첫 화면과 마지막 구간에 동일한 전환 버튼 배치
- 인스타그램 인앱 브라우저의 작은 화면에서도 입력창과 버튼이 한 화면 안에서 명확히 보이도록 설계
- 장식용 이미지보다 로드뷰 건물, 창문, 에어컨, 책상 등 내용과 직접 관련된 단순 일러스트 또는 아이콘을 사용

## 7. 기술 구조

### 프런트엔드

- 빌드 과정이 필요 없는 정적 `HTML`, `CSS`, `JavaScript`
- 모바일 반응형, 시맨틱 마크업, 키보드 접근성, 명확한 폼 오류 안내
- 이메일 형식 검사, 중복 제출 방지, 제출 중 상태 표시
- 기본 Open Graph·검색 메타데이터와 공유 이미지 자리 제공

### 이메일 API

- Vercel Serverless Function 한 개: `POST /api/send-checklist`
- Resend API를 서버에서 호출해 체크리스트 이메일 발송
- 환경 변수: `RESEND_API_KEY`, `RESEND_FROM_EMAIL`, `RESEND_REPLY_TO_EMAIL`, 선택적으로 `RESEND_SEGMENT_ID`
- `RESEND_SEGMENT_ID`가 설정된 경우 후속 검증 연락에 동의한 이메일만 Resend Contact로 만들고 해당 Segment에 저장
- API 키는 클라이언트 번들에 포함하지 않는다.

### 데이터 흐름

1. 사용자가 이메일과 필수 동의, 선택 동의를 제출한다.
2. 브라우저가 `/api/send-checklist`에 JSON을 전송한다.
3. 서버가 입력 형식, 허니팟, 요청 크기를 검사한다.
4. 선택 동의가 있으면 Resend Contact를 만들고 지정한 Segment에 연락처를 등록한다.
5. 사용자에게 25개 항목과 공식 주거 혜택 확인 경로가 담긴 HTML 이메일을 발송한다.
6. 성공 또는 실패 결과를 페이지의 접근 가능한 상태 메시지로 보여준다.

별도 데이터베이스는 두지 않는다. 이메일 발송과 선택 동의 연락처 관리는 Resend에서 처리한다.

## 8. 오류·안전·개인정보 처리

- 유효하지 않은 이메일은 클라이언트와 서버 양쪽에서 거부
- 숨겨진 허니팟 필드로 단순 봇 제출 차단
- 동일 브라우저에서 연속 클릭 방지
- 외부 서비스 장애 시 이메일을 저장했다고 오해하게 만들지 않고 발송 실패를 명확히 안내
- 필수 개인정보 처리 안내와 선택 마케팅 동의를 분리
- 개인정보 처리방침에는 수집 항목, 목적, 보관 주체, 보관 기간, 받은 체크리스트 이메일에 답장하는 삭제 요청 방법을 명시
- 체크리스트는 생활 경험 기반 참고 자료이며 시설 상태와 지원 자격을 보장하지 않는다는 안내 포함

## 9. 검증 기준

- 320px 이상 모바일 화면에서 가로 스크롤, 겹침, 잘림이 없음
- 첫 화면에서 문제 문장과 CTA가 명확히 보임
- 이메일 미입력, 잘못된 형식, 필수 동의 누락 시 각각 올바른 오류 표시
- 정상 요청 시 발송 중 상태 후 성공 메시지 표시
- API 실패 시 재시도 가능한 오류 메시지 표시
- 키보드만으로 폼을 제출할 수 있고 포커스 순서가 자연스러움
- API 키나 내부 설정값이 정적 파일 또는 Git 기록에 포함되지 않음
- Vercel 배포 환경에서 실제 테스트 이메일 수신 확인
