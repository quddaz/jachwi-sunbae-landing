# 자취선배 Gmail 발송·Resend 연락처 저장 설계

## 목표

별도 발신 도메인을 구매하지 않고, 랜딩 페이지 방문자가 입력한 이메일로 고시원 계약 전 25개 체크리스트를 즉시 발송한다. 후속 연락에 명시적으로 동의한 이메일은 Resend Contacts의 전용 Segment에 저장한다.

초기 대상은 약 30명이며, 별도의 Supabase 데이터베이스는 도입하지 않는다.

## 결정 사항

- 이메일 발송은 개인 Gmail 계정과 Gmail 앱 비밀번호를 사용하는 SMTP 방식으로 변경한다.
- 발신자 주소와 답장 주소는 같은 Gmail 주소를 사용한다.
- 기존 HTML·일반 텍스트 25개 체크리스트 본문은 그대로 재사용한다.
- 필수 개인정보 수집 동의는 이메일 1회 발송에 사용한다.
- 선택 항목인 후속 연락 동의가 있는 경우에만 Resend Contacts에 이메일을 저장하고 지정 Segment에 연결한다.
- Resend Contact 저장 실패가 체크리스트 발송 자체를 막지는 않지만, 이메일 원문을 남기지 않는 서버 로그로 실패를 기록한다.
- Gmail 발송에 실패하면 성공 화면을 표시하지 않고 재시도 안내를 반환한다.

## 시스템 구성

### 브라우저

현재 폼에서 다음 값을 `POST /api/send-checklist`로 전송한다.

- `email`: 체크리스트를 받을 이메일
- `privacyConsent`: 1회 발송을 위한 필수 동의
- `followUpConsent`: 후속 연락 및 Resend Contacts 저장을 위한 선택 동의
- `company`: 봇 차단용 숨김 필드

### Vercel 함수

기존 입력 검증과 요청 크기 제한을 유지한다. 검증 후 작업 순서는 다음과 같다.

1. 후속 연락에 동의했고 Resend 설정이 존재하면 Resend Contact와 Segment 등록을 시도한다.
2. 기존 이메일 템플릿을 렌더링한다.
3. Gmail SMTP로 HTML과 일반 텍스트 버전을 함께 발송한다.
4. Gmail 발송 결과에 따라 성공 또는 오류 응답을 반환한다.

### 외부 서비스

- Gmail: 체크리스트 이메일 발송
- Resend Contacts: 후속 연락 동의자 이메일 저장
- Vercel: 서버 함수 실행과 비밀 환경 변수 보관

## 환경 변수

- `GMAIL_USER`: 발신에 사용할 Gmail 주소
- `GMAIL_APP_PASSWORD`: Google 계정에서 발급한 앱 비밀번호
- `RESEND_API_KEY`: Resend Contacts API 호출용 키
- `RESEND_SEGMENT_ID`: 후속 연락 동의자를 저장할 Segment ID

비밀값은 소스 코드나 Git 저장소에 기록하지 않고 Vercel의 암호화된 환경 변수에만 저장한다. Preview와 Production 환경은 필요한 범위에 맞게 각각 설정한다.

## 개인정보 처리 원칙

- 사용자가 체크리스트 수신을 요청하면 Gmail 발송 과정에서 이메일 주소가 처리된다.
- 후속 연락에 동의하지 않은 사용자는 Resend Contacts에 저장하지 않는다.
- 후속 연락 동의자는 Resend에서 구독 취소 처리할 수 있어야 한다.
- 현재 페이지의 개인정보 안내에는 처리 목적, 저장 대상, 보관 및 삭제 요청 방법을 실제 동작과 일치하도록 표시한다.
- Gmail과 Resend의 서비스 로그에는 각 서비스 정책에 따른 기술 기록이 남을 수 있음을 운영상 고려한다.

## 오류 처리

- Gmail 설정 누락: `SERVER_NOT_CONFIGURED`
- Gmail 인증 또는 발송 실패: `SEND_FAILED`
- Resend Contact 저장 실패: 발송은 계속하고 개인정보가 포함되지 않은 경고 로그만 기록
- 잘못된 이메일 또는 필수 동의 누락: 기존 4xx 검증 응답 유지
- 중복 제출: 버튼 로딩 상태로 브라우저 내 연속 클릭을 막는다. 별도 데이터베이스가 없는 이번 범위에서는 서버 간 중복 제거 상태를 저장하지 않는다.

## 테스트

- Gmail 전송 함수가 올바른 발신자, 수신자, 제목, HTML, 일반 텍스트를 받는지 단위 테스트한다.
- 후속 연락 동의가 없으면 Resend Contacts를 호출하지 않는지 확인한다.
- 후속 연락 동의가 있으면 지정 Segment로 Contact를 생성하는지 확인한다.
- Resend 저장 실패 후에도 Gmail 발송이 이어지는지 확인한다.
- Gmail 발송 실패 시 API가 502와 `SEND_FAILED`를 반환하는지 확인한다.
- 기존 체크리스트가 정확히 25개인지 확인하는 테스트를 유지한다.
- 배포 후 소유자 이메일로 실제 1회 발송하여 수신함·스팸함·모바일 표시를 확인한다.

## 범위에서 제외

- Supabase 또는 별도 데이터베이스
- 자동 뉴스레터 및 대량 캠페인
- 사용자 계정과 로그인
- 발송 통계 대시보드
- 자체 도메인 기반 발송

개인 Gmail은 소규모 검증용으로만 사용한다. 발송량이 초기 목표인 약 30명을 넘어 지속적으로 증가하면 자체 도메인을 연결한 전문 발송 서비스로 이전한다.

사용자 수나 저장할 속성이 늘어 지역, 유입 경로, 동의 이력, 발송 상태를 직접 조회해야 할 때 Supabase 도입을 다시 검토한다.
